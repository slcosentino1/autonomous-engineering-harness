# Architecture and Implementation Plan Prompt

Read the approved requirements, current architecture, target instructions, existing decisions, and repository state.

Describe the smallest architecture that satisfies scope: responsibilities, data flow, interfaces, persistence, concurrency, errors, recovery, deployment, and security where relevant. Record consequential decisions with alternatives and consequences; leave unresolved choices open.

Create small implementation increments with dependencies, likely components, acceptance criteria, documentation impact, required/optional validations, evidence expected, and risk band. Include failure and concurrency scenarios proportional to risk. Keep future capabilities clearly marked as planned.

Do not add infrastructure, abstractions, requirements, or dependencies without evidence of need. Preserve the current plan structure when revising it unless the user authorizes a redesign. Report open decisions and approval gates before implementation.

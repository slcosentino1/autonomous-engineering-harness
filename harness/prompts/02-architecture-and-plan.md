# Architecture and Implementation Plan Prompt

Read the approved requirements, current architecture, target instructions, existing decisions, repository state, and engineering discovery. Complete and persist the scenario analysis before finalizing the plan.

Describe the smallest architecture that satisfies scope: responsibilities, data flow, interfaces, persistence, concurrency, errors, recovery, deployment, and security where relevant. Record decisions with category (`engineering`, `technical_tradeoff`, `product_business`), alternatives, rationale, and whether human input is actually required. Decide routine engineering defaults autonomously. Ask for product input only when behavior or business outcomes are materially ambiguous. Record assumptions separately with impact and reversibility.

Create small implementation increments with dependencies, likely components, acceptance criteria, documentation impact, required/optional validations, evidence expected, and risk band. Map discovered scenarios to expected behavior and specific verification. Include failure and concurrency scenarios proportional to risk. Keep future capabilities clearly marked as planned. Paths describe implementation/review scope inside the already authorized workspace; they do not create per-operation approval gates.

Do not add infrastructure, abstractions, requirements, or dependencies without evidence of need. Preserve the current plan structure when revising it unless the user authorizes a redesign. Record only genuine product decisions or separately restricted operations as pending. If a decision blocks only part of the assignment, set `decision` to `NEEDS_HUMAN_INPUT`, return the complete plan, mark only dependent increments with `blocked_by_decision: true`, and allow the orchestrator to run independent increments before it waits for the answer. If nothing is safely independent, return a decision-only response. Batch related questions into one clear decision when they share an owner and can be answered together; never treat a proposal as approval.

# Implement One Increment Prompt

Implement only the authorized increment in the identified target repository.

1. Re-read target instructions, applicable requirements/decisions, the increment plan, and working-tree status.
2. Confirm scope and acceptance criteria. Preserve unrelated and pre-existing changes.
3. Make the smallest maintainable change consistent with applicable local instructions and conventions; add or update focused tests.
4. Assess documentation impact and update the smallest relevant existing target document alongside material behavior, architecture, interface, data, security, operational, or maintenance changes. Avoid duplicate or trivial Markdown files.
5. Do not add dependencies, infrastructure, or product behavior outside approved scope. Follow the operation-specific authorization matrix; file-write approval does not authorize installation, downloads, external calls, Git commits, or destructive operations. Use `harness/safe_writer.py` for target directory creation and file creation/replacement with the approved preflight scope config; do not bypass it with direct edits. For nested directory creation, every missing path component must independently be covered by the explicit scope before creation begins. Existing parents are opened without following symlinks; an existing requested destination fails, and partial nested creation is retained and reported rather than deleted. The writer relies on the documented single-writer assumption and does not prevent arbitrary non-cooperating writers racing after its final check. Pause human/automation edits during the active write workflow and stop to revalidate if unexpected changes appear. `O_NOFOLLOW` does not protect against hard links: existing files with `st_nlink>1` are rejected, and replacement requires the recorded baseline SHA-256 plus immediate identity/content rechecks.
6. Run authorized validations that are available. Containers must run without network egress by default; local service access, external egress, image pulls, and dependency downloads each need separate authorization. If the runtime cannot guarantee isolation, do not execute automatically. Record exact commands and observed outcomes, immutable `content:<sha256>` identity, manifest reference and scope; distinguish blocked or stale evidence from passes.
7. Correct confirmed defects in scope. If the content identity changes, treat prior evidence and reports as ineligible for the new gate; rerun checks selected by impact analysis, create current evidence for every required criterion, and obtain every required review on the final identity.
8. Update the target's tracking artifacts with actual changes, documentation references, evidence, limitations, authorizations, and status.
9. Do not start the next increment until the required review/approval boundary is satisfied.

Report changed files, behavior, tests and results, remaining risks/blockers, and repository status. Do not claim completion without evidence for every required criterion.
